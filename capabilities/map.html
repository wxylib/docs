Where wxylib core stands on the spectrum

The structured half of the ladder (R0 to R3) is built end to end and matches GDAL 3.12 on every fixture. R6 features are in as inputs to extraction, not yet as data the model holds. R3', R4 and R5 exist only as type slots. The full API lives in Rust and the CLI; Python and R bind three in-memory functions, and the browser binds COG warping.

The ladder

Each rung stores strictly more than the one before (design doc 02, section 3). Every Positions variant in wxy-domain exists, so types will not change when rungs arrive; only R0 to R3 evaluate positions. Arrows are the conversions that run today.

Rung by verb

Rows are rungs; columns are the things the library does. The warp, points and zonal columns all go through one plan seam in wxy-warp, so a rung that warps also extracts.

CRS input
Pure Rust proj4rs everywhere: EPSG codes and PROJ strings, no WKT or PROJJSON. wxy warp --crs takes EPSG only, since GeoZarr proj: has nowhere to record a PROJ string. Real PROJ is the open question (rust-proj-capability); proj4rs lacks polar LAEA and AEQD.
Packaging
Docker images for the CLI, Python and R (wxylib/images). No crates.io release yet by choice; rwarp is a git dependency. CI on Ubuntu only.
Shared layers
C ABI (wxy-ffi) and Arrow interchange are the intended base for Julia, DuckDB, Go and JS hosts. Neither exists yet.

Potential: what the next steps open up

S3c · parked on m06 questions

Flat refs store

A zarrs storage over the mdim-refs Parquet export. Virtual data reads without writing an Icechunk repo first, plans report real stored bytes, and the cache sees every virtual read. It is also the cheapest route to bindings, since a table is all a host needs to hand over.

S6 · spikes exist

Bindings of the real surface

Python and R move from in-memory functions to open, warp, points, zonal and explain on files and stores. Most of the work is a repin and a thin layer, because plans and options already serialise.

S7

The virtual scheme

Select, remap, combine and compute, serialised and written by the library: the VRT replacement, mosaics with gdalbuildvrt-style validation, and the place features and meshes join grids.

S8 and later

Mesh half of the ladder

  • R5 explicit meshes via UGRID, conversion first.
  • R6 as GeoArrow inside the model, so features are data and not only queries.
  • R4 schemes (HEALPix, H3, L3 bins) as a CellScheme.
R1 to R3 gaps (m07)

Index-space depth

  • CF grid_mapping, so rotated-pole and geos read in their frame.
  • Periodic and folded dims; cubed-sphere patches.
  • Vertical formula_terms as R3' with field terms.
  • netCDF input, 1D CF bounds, NaN in geolocation.
cross-cutting

The transform verb and PROJ

transform (positions on every rung) is decided but not built; today positions only move inside warp and extraction. A PROJ-backed frame would lift the EPSG-only limit, WKT and PROJJSON with it, and the missing projections.
